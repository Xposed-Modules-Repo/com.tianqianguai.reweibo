# 日志页面卡顿与设置同步错误提示

## 证据与范围

用户提供的11月5日日志，在打开日志预览附近出现最高695ms帧耗时，以及630–693ms的日志页面回调排队。代码在主线程把最多256Ki字符的可选中文本一次交给TextView，随后强制fullScroll到底部；文本测量、换行和布局并不包含在后台文件读取耗时中。这是本次修复的直接热点，但不能据此解释所有页面或所有卡死。

截图提示对应日志的 `Unknown URI content://com.tianqianguai.reweibo.settings/settings/weico_timeline_cache_days`。仅凭此信息不能认定用户一定安装HMA，因此提示使用条件说明，不自动修改隐藏规则或权限。

## 修改

- 保留最多256Ki字符的原预览窗口，后台按最多4Ki字符分成页面；默认展示最后一页，可前后翻页。长行允许跨页，不截断内容，不拆开UTF-16代理对。
- 不再对整份预览强制滚到底部；每次只布局当前页。关闭页面或后续刷新会使旧结果失效，排队的过期读取任务直接跳过。
- 保留文字选择；复制菜单提供当前页与全部预览两种操作，完整日志导出并分享保持原有行为。
- 设置同步失败显示停留式对话框：失败项、模块服务不可见/权限拒绝/其他写入失败的原因与建议。Unknown URI提示检查ReWeibo可见性和用户/分身空间，明确无需关闭所有隐藏规则或清数据。
- 明确说明本地副本已经保存、模块端可能部分更新、尚未完成同步；保留当前选择供重试，不伪报成功。

## 验证

LogUiFixTest覆盖分页全部内容可还原、长行与emoji边界、空预览、Unknown URI提示、权限错误与一般错误的区分。LogFileToolsTest和LogTerminalContractTest回归原有筛选、快照、导出和可选中能力。

Debug构建成功，三组针对性测试通过。第一次测试进程因本机包含空格的native library路径解析失败而无法启动；改用本次进程专用最小PATH和独立Gradle进程后通过，未改项目或系统环境配置。

本次未安装到设备，尚未验证真实TextView翻页帧耗时、触摸选择和设置失败弹窗呈现。编译与单测不能替代真机结论；未声称695ms停顿或所有假死已实测消失。
