# 自动识别“划不动”

持久诊断开启时，首页手势异常自动带上日志时间、手势编号、开始uptime、页面和操作上下文。用户无需记住准确时间，反馈后导出日志即可检索 `module=gesture`。

- `gesture_not_delivered`：明显竖向移动未进入所观察的首页RecyclerView；可能被子控件或弹窗消费，不直接认定模块故障。
- `gesture_no_scroll`：手势到达列表、移动超过48dp、至少两次MOVE，但无实际滚动且起止位置相同，当前方向仍可滚动。
- `possible_anchor_pullback`：有实际滚动、最后回到起点附近，期间存在模块定位或Adapter更新请求；只是关联线索，可能是用户往返滑动，不能单独认定根因。
- `module_during_gesture`：手势或结束后一秒内模块干预过列表，但没有满足回拉条件。
- 边界、点按、多指/取消操作不作为上述异常；详细模式可查看其摘要。

摘要包含移动距离、实际滚动距离/次数、首个可见位置与像素偏移、是否到边界、模块干预次数、最后一次干预来源和目标位置。已有主线程心跳/堆栈监测继续负责真正阻塞，两类证据需结合分析。模块定位记录表示请求，可能因宿主拒绝而未应用。

性能约束：只观察当前首页的一次手势；MOVE和滚动回调仅更新固定字段，无列表扫描、反射、字符串或日志写入。首尾各采一次可见位置及子View偏移；结束最多调度一次一秒后的检查，新手势、取消、页面暂停和热重载会清掉旧回调。正常模式异常同类别最多两秒一条，日志仍走既有有界后台写入。关闭持久诊断不启动观察。

验证：4项纯行为测试覆盖未投递/边界/不滚动/疑似回拉、点按与取消排除、状态重置；主机100万次move+scroll累计约10ns/次，仅为计数器微基准，不含Android Hook和首尾采样开销，不能代替真机性能验证。本次Debug构建通过，未安装、未制造卡顿或证明所有故障均可自动定位。

此追加沿用日志页修复工作树，保留分页、完整复制/导出和明确设置错误提示。远端查询遇TLS握手失败，未覆盖主目录任何修改；未提交推送或发版。
